## Non-functional requirements

| Requirement | Decision | Status | Milestone |
|-------------|----------|--------|-----------|
| Lazy loading | List page 1 → detail → files pages → highlight, loaded on demand rather than up front. The list's page 1 loads eagerly on start; reaching the last loaded row of a section with more pages triggers `Store.LoadMore`. `Store.OpenPR` fetches a pull request's detail only when opened (cache-first, then network). `Store.LoadFiles` fetches a pull request's changed files one REST page at a time (cache-first, then `If-None-Match`), parsing each page's patches and enqueueing a 2-worker highlight pool per page as it lands — but nothing in the store calls `LoadFiles` on its own initiative when a pull request opens (deliberately: opening the Files tab is what should trigger it), so it is data-complete but not yet reachable from the UI. | In progress (data done, UI pending) | M1a, M1b, M2 |
| Cache | Disk cache with ETag revalidation for REST and stale-while-revalidate for GraphQL. The on-disk `Entry{Body, ETag, FetchedAt}` store (`internal/cache`) with atomic writes and PR-scoped invalidation exists; `internal/store` caches search results per section, the current pull request's detail, and its changed files (`Get`/`Put` under `cache.PRKey(..., "files/page-<n>")` per page, `Entry.ETag` round-tripped as `If-None-Match`/a fresh `ETag` response header) — all three stale-while-revalidate: a cached result is shown immediately, marked stale, while a network refetch runs. Search and detail caching are wired end-to-end into the TUI (stale list rows render dimmed; the PR tab's header shows a "(cached)" marker while `DetailState().Stale`); files caching is implemented and tested in `internal/store` but has no UI to surface `FilesState().Stale` yet (M2's UI slice). | In progress (data done, UI pending) | M1a, M1b, M2, M3b |
| Refresh | 5-minute auto refresh (configurable via `refresh_interval`) for the list and the current PR. `internal/store.StartAutoRefresh`'s ticker calls both `Store.Refresh()` and `Store.RefreshPR()` (a no-op while no pull request is open); `R` (`global.reload`) forces an immediate cache-skipping reload of both via `Store.Reload()`, which also calls `Store.ReloadPR()`. Opening a pull request from the list (`Store.OpenPR`) is done. | Done | M1a, M1b |
| Drafts | Drafts persisted on every change and restored across PR switches/reloads/restarts. | Planned | M3a |
| Auth | Reused from `gh` (`GH_TOKEN`/`GITHUB_TOKEN` override; GHES via gh host config). Implemented by `gh.New` via go-gh's `auth.DefaultHost`/`auth.TokenForHost`. | Done | M1a |
| Language | All docs, comments, commits, and UI strings in English. | Done | (ongoing convention) |
| Stack | Go 1.26, tview + tcell only (no BubbleTea), no mouse support. `go.mod` pins `github.com/rivo/tview v0.42.0` and `github.com/gdamore/tcell/v2 v2.13.10` as direct dependencies; the TUI never calls any mouse-related tcell/tview API. | Done | M1a |

## Open items to confirm against the live API

- `reviewThreads` includes the viewer's PENDING threads (M3b). If not, merge the `reviews(states:[PENDING]).comments` connection into the thread model.
- Mixed-side ranges (`startSide: LEFT`, `side: RIGHT`) accepted or rejected (M3b).
- Negated qualifiers (`-user-review-requested:@me`) accepted by search (M1a); otherwise rely on dedupe only.
- Key events on the user's terminal: `internal/ui/keys.Normalize` and the router are implemented and unit-tested for both legacy (`KeyBackspace`) and CSI-u (`KeyCtrlH`) reporting of Ctrl-H; validating against the user's actual terminal is still open (`go run ./cmd/gprt`).

## Known limitations (v1)

- Multi-line range comments are single-side only (all deletion lines or all addition/context lines, not a mix).
- No mouse support.
- No local checkout of a pull request's branch.
- No CI rerun and no check-run log viewing; checks can only be viewed and opened in the browser.
- The vim editor's own keys are fixed and cannot be remapped through config.
- Actions bound by the default keymap but not implemented until a later milestone (`list.new_pr`, `pr.*`, `diff.*`, `thread.*`, `comment.*`, `files.toggle_tree`) are silently ignored by the M1a router rather than showing a "not implemented" toast for every exploratory keypress; `?`/`:help` lists every binding regardless.
- The **[Files]** detail tab remains a placeholder ("Files view arrives in M2") until M2; the **[PR]** tab (description, checks, conversation) is done as of M1b.
