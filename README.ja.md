# gprt
[English](README.md) | 日本語
GitHub PR TUI アプリケーション

設計・要件・キーバインドの詳細ドキュメント(`docs/`)は英語のみです。

`gprt` は、ターミナルを離れることなく GitHub のプルリクエストを操作できるターミナルユーザーインターフェース(TUI)です。複数のリポジトリにまたがるプルリクエストを一覧表示し、説明文・チェック・差分(diff)を表示するほか、vim スタイルのコメント、レビュー、リアクション、メンションにも対応しており、すべてキーボードのみで操作できます(マウス操作はありません)。認証は `gh` CLI のものを再利用し、データはディスクにキャッシュされ、バックグラウンドで定期的に更新されます。

## ステータス

マイルストーン **M4(レビュー送信、リアクション、実際のメンション)** は、M1a の基盤・PR 一覧、M1b の PR タブ、M2 の Files タブ、M3a の vim エディタ/コンポーザー/下書き/一般コメント、M3b の diff 上のレビューコメントに加えて完成しています。**M5** の UI 部分――PR 編集フォーム、マージ/クローズ/再オープン、PR 作成フォーム――も完了しています。`go run ./cmd/gprt` を実行すると、自分のプルリクエストがセクション(直接レビュー依頼、チームレビュー依頼、自分の PR、その他関与している PR)ごとにグループ化され、ソート・色分けされた状態で一覧表示されます。`/` で絞り込みができ、5 分ごとの自動更新と手動の `R` リロードで最新の状態が保たれます。プルリクエストを選択する(`Enter`/`l`、あるいはカーソルを移動するだけでも可)と **[PR]** タブが開き、タイトル、状態、base←head、作者、タイムスタンプ、ラベル、レビュー判定とレビュアー、diff の統計、軽く Markdown 装飾された説明文、チェック一覧、そして会話の全タイムライン(コメント、レビュー、コミット、イベント)が表示されます――これらはすべて `j`/`k`/`gg`/`G`/`Ctrl-d`/`Ctrl-u` で操作でき、`o` で選択中の項目をブラウザで開けます。`c` は新しい一般コメント用のコンポーザーを開き、自分のコメント上での `e`/`d` はそれぞれ編集、(確認後に)削除を行います。また、説明文ブロック、issue コメント、レビューの上で `a` を押すと、それに対するリアクションピッカーが開きます。**[Files]** タブに切り替える(`gt`/`Ctrl-l`)と、変更されたファイルのディレクトリツリー(状態を表す記号、diff の統計、スレッド数マーカー、下書きが保存された行を示す `✎` マーカー付き)が diff ビューと並んで表示されます。diff ビューには、ガター付きでシンタックスハイライトされたハンク、インラインのレビュースレッド(`za`/`zR`/`zM` で折りたたみ可能、`]c`/`[c` で移動可能、未公開レビューの自分のコメントには `PENDING` バッジ)、ファイル間を移動する `]f`/`[f`、ビジュアル行選択の `V`、横に長い行を水平スクロールする `zh`/`zl` があります。`c` は新しい行/範囲コメント用のコンポーザーを開きます(既存のスレッド上では返信になります――`r` と同じ動作)。`C` はファイル全体へのコメント、`x` はスレッドの解決/未解決の切り替えです。スレッド上での `e`/`d` は、そこにある自分のコメントを編集または削除します(複数ある場合はメニューが表示されます)。スレッド上で `a` を押すとそのコメントへのリアクションピッカーが開きます――自分のコメントに限らずすべてのコメントにリアクションでき、複数ある場合はメニューが表示されます。行/範囲/ファイルコメントや返信を送信する際には、GitHub と同じ選択肢――今すぐ送信する「Add single comment」か、レビューに積み立てる「Add to review」――が提示されます。ただし、既にペンディング中のレビューが存在する場合は、新しいコメントは自動的にそのレビューに追加されます。`p` は開いているプルリクエストのペンディング中のレビューコメントとローカルの下書きを一覧表示します(`Enter` で編集用に開く、`d` で削除、`D` でペンディング中のレビュー全体を破棄)。`S` はレビュー送信ダイアログ(Approve / Request changes / Comment、それぞれレビュー本文用のコンポーザーを持つ)を開き、`Store.SubmitReview` を呼び出します。成功すると一覧が更新されます。リアクションピッカーには GitHub の 8 種類のリアクションすべてが現在のカウントとともに表示され、`Enter`/`Space` で切り替えられます。複数回切り替えられるよう、ピッカーは開いたままになります。**[PR]** タブと diff のコンポーザーはどちらも、カウント指定・オペレーター・undo/redo を備えたノーマル/インサート/ビジュアルモードでの編集、`@` メンション補完(まず PR の参加者、続いてリポジトリの実際のメンション可能なユーザー)、そして `:e` で `$EDITOR` によるバッファ編集ができます。`Ctrl-s`/`:w` で送信、`:q`/`:q!` で下書きを保持または破棄してコンポーザーを閉じます――下書きはディスクに保存され、PR の切り替え、リロード、`gprt` の再起動をまたいで保持され、ステータスバーには現在のプルリクエストが持つ下書きの数(`✎ N`)が表示されます。ナビゲーション/アクション用のキーはすべて設定でリマップ可能です(エディタ自体のキーは固定です)。`?` で現在有効なキーバインドを確認できます。

M4 に加えて、M5 の UI 部分の前半ではプルリクエストの編集とライフサイクルコマンドが追加されています。`E`(`ContextPR`/`ContextFiles`/`ContextDiff`、閲覧者がそのプルリクエストを編集できない場合はトーストで拒否されます)は編集フォームを開きます。フォームにはタイトル、base ブランチ(入力に応じてリポジトリのブランチから自動補完)、複数選択リストを開く「Labels」ボタン(`Space` で切り替え)、現在リクエストされているレビュアー(削除可能)・入力に応じて絞り込まれるリポジトリのメンション可能なユーザー(追加可能――全く新しい個人ユーザー)・チーム検索(追加可能)を組み合わせた複数選択リストを開く「Reviewers」ボタン、そして Draft チェックボックスがあります。`Ctrl-s` は実際に変更された項目のみを保存し(変更がなければ「nothing to save」)、各部分ごとの成否をトーストで表示します。`Esc` は、何か変更があった場合にのみ先に破棄確認を行います。PR タブの説明文ブロックで `e` を押すと、一般コメントではなくプルリクエスト自体の本文用のコンポーザーが開きます。そこでの `d` は何もしません。`:merge`・`:close`・`:reopen` コマンド(`n` の隣で誤って押されないよう、単一キーには割り当てられていません)は、それぞれ対応するミューテーションを呼び出す前に確認ダイアログを表示します――`:merge` はまずリポジトリで許可されているマージ方法を読み込み(選択肢が 1 つしかない場合はそれをあらかじめ選択)、コミットの見出し/本文フォームを表示します。

`n`(一覧画面のみ)は、M5 の UI 部分のもう半分にあたる PR 作成フォームを開きます。フォームには、自分のリポジトリに対してあいまい検索で自動補完される Repository フィールド(一覧にない `owner/name` を正確に入力しても動作します)、編集フォームの base フィールドと同じ方法で自動補完される Head/Base ブランチフィールド、Title フィールド、作成予定のプルリクエスト本文に対して同じ vim コンポーザーを開く「Edit body」ボタン、「Reviewers」ボタン(編集フォームのオーバーレイを再利用)、Draft チェックボックスがあります。リポジトリを選択すると、Base にそのデフォルトブランチがあらかじめ選択され、本文がまだ空であれば、そのリポジトリの最初のプルリクエストテンプレートから本文が事前入力されます。`Ctrl-s` はプルリクエストを作成する前にローカルでバリデーションを行い(リポジトリ、異なる head/base ブランチ、タイトル)、作成後はそれを開いて番号をトーストで表示します。失敗した場合――作成済みのプルリクエストに対するレビュアーリクエストが後から失敗したケースも含め――入力内容を失わずに状況を通知します。`Esc` は、何かを入力した後にのみ先に破棄確認を行います。他のすべてのダイアログと異なり、無関係なプルリクエストへの切り替えではこのフォームやその本文コンポーザーは閉じられません。要件・マイルストーンごとの全体的なステータスについては [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) を参照してください。

## 機能

| # | 機能 |
|---|------|
| F1 | 複数リポジトリにまたがる PR 一覧(組み込み/カスタムの検索セクション、状態フィルタ) |
| F2 | TUI 内から PR を作成(リポジトリ/ブランチピッカー、テンプレート、レビュアー、ドラフト) |
| F3 | 変更されたファイル: ファイルツリー + 非同期シンタックスハイライト付きの unified diff とインラインコメントスレッド |
| F4 | レビュー送信: 単一コメントまたはペンディングレビュー(Approve / Request changes / Comment) |
| F5 | エディタ内での `@` メンション自動補完 |
| F6 | PR 本文・コメント・レビューに対する GitHub の 8 種類のリアクションの切り替え |
| F7 | ハイブリッド編集: アプリ内の vim ライクなモーダルエディタ、または `$EDITOR` へのサスペンド |
| F8 | PR のタイトル/本文/base/レビュアー/ラベル/ドラフト状態の編集、自分のコメントの編集/削除 |
| F9 | ブラウザで開く、確認付きの `:` コマンドによるマージ/クローズ/再オープン |
| F10 | CI チェック: ロールアップアイコン、チェック一覧、PR と共に更新、ブラウザでチェックを開く |
| F11 | ナビゲーション/アクションキーはすべて設定でリマップ可能(エディタ自体のキーは固定) |

上記の機能はすべて完了しています。F1(PR 一覧)、F3(Files タブ)、F4(レビュー送信)、F5(メンション)、F6(リアクション)、F7(vim エディタと `:e`)、F10(CI チェック、一覧と PR タブ)、F11(キーのリマップ)、および F9 のブラウザで開く部分が先に完成しました。F8(コメントの編集/削除、PR メタデータ)は、issue コメントとレビューコメントの両方を一気通貫でカバーし(追加/編集/削除、コンポーザーからのトリガー、複数該当時の選択メニュー、確認あり)、プルリクエスト自体の本文も同じ方法で編集でき(説明文ブロックでの `e`)、`E` でタイトル/base/ラベル/レビュアー/ドラフトを編集するフォームが開きます。F9 の `:merge`/`:close`/`:reopen` コマンドはそれぞれ確認ダイアログの後ろにあり、F2(TUI からのプルリクエスト作成、`n`)で全機能が揃いました。項目ごとのステータスについては [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) を参照してください。

## 必要要件

- Go 1.26
- ログイン済みの [`gh` CLI](https://cli.github.com/)(`gh auth login`)、または `GH_TOKEN` / `GITHUB_TOKEN` 環境変数の設定

## インストール

```sh
go install github.com/hirano00o/gprt/cmd/gprt@latest
```

(リリース後に利用可能になります――現時点ではタグ付きリリースはまだ存在しません。現在は `go build ./cmd/gprt` でローカルの `gprt` バイナリをビルドできます。)

## 使い方

```sh
go run ./cmd/gprt              # or: gprt, once built/installed
go run ./cmd/gprt --debug      # log to <state dir>/gprt.log (see below)
go run ./cmd/gprt --config /path/to/config.yaml
go run ./cmd/gprt --version
```

| Flag | 効果 |
|------|------|
| `--config <path>` | デフォルトの設定ディレクトリの `config.yaml` の代わりにこのファイルを使用する。デフォルトのパスと異なり、ここで指定したファイルが存在しない場合は、デフォルト値へ黙ってフォールバックせず起動エラーになる |
| `--debug` | `<state dir>/gprt.log` に JSON 形式のデバッグログを書き込む(`GPRT_DEBUG` でも有効化可能) |
| `--version` | バージョンを表示して終了する |

## 設定

`gprt` は任意の、厳密な YAML 設定ファイルを読み込みます。すべてのキーは省略可能で、ファイルが存在しなくてもエラーにはなりません。

設定ディレクトリの優先順位:

1. `GPRT_CONFIG_DIR` ―― 設定する場合は絶対パスである必要があります。絶対パスでない値が設定された場合は、黙ってスキップされるのではなく起動エラーになります(これは gprt 独自の変数であるため、そこでのタイプミスは見逃されるべきではありません)
2. `XDG_CONFIG_HOME/gprt` ―― XDG Base Directory 仕様に従い、絶対パスでない `XDG_CONFIG_HOME` は黙って無視されます
3. `~/.config/gprt`

設定ファイルは、そのディレクトリ内の `config.yaml` です。例えば `~/.config/gprt/config.yaml` になります。

```yaml
host: github.com          # default: gh's default host
refresh_interval: 5m
icons: unicode            # unicode | nerd
editor: ""                # overrides $EDITOR for :e
browser: ""               # overrides $BROWSER
highlight_style: github-dark  # "" or any name from chroma's styles.Names(); rejected at startup if unknown
tab_width: 4
list:
  state: open             # open | closed (not merged) | merged | all
  sections:
    - name: Backend
      query: "org:acme label:backend"
keys:                     # action ID → key sequence (vim notation); unspecified actions keep defaults
  global.toggle_list: "<C-w>o"
  diff.comment: "c"
  pr.submit: "S"
```

`gprt` が使用するその他のディレクトリ:

- キャッシュ(ETag で再検証される API レスポンス): `~/.cache/gprt`
- 状態(下書きとデバッグログ): `~/.local/state/gprt`

## キーバインド

キーバインドは vim スタイルで、`keys:` 設定セクションを通じてリマップ可能です(下記のコンポーザー自体の vim キーは固定です)。`j`/`k`/`gg`/`G`/`Ctrl-d`/`Ctrl-u` は、一覧、**[PR]** タブ、ファイルツリー、diff のいずれかでカーソルを移動します。`/` は一覧を絞り込み、`Enter`/`l` は PR を開き(ツリーではディレクトリ/ファイルを開き)、`o` は一覧の現在の PR(PR タブで選択中のブロック、チェック自体の詳細 URL、diff のスレッド/ファイルの URL)をブラウザで開き、`R` はリロードします。`Ctrl-w h`/`Ctrl-w l` は、一覧とアクティブなタブが持つ詳細ペインの間でフォーカスを循環させます(一覧 ⇄ PR タブ、または 一覧 → ツリー → diff)。`Ctrl-w o` は一覧カラムの表示切り替え、`Ctrl-w t` はファイルツリーの表示切り替え、`gt`/`gT`/`Ctrl-l`/`Ctrl-h` は **[PR]**/**[Files]** タブを切り替えます。diff 上では、`V` でビジュアル行選択を開始し(`Esc` でキャンセル)、`za`/`zR`/`zM` でスレッドの折りたたみ/展開、`zh`/`zl` で水平スクロール、`]c`/`[c`/`]f`/`[f` でスレッド/ファイル間を移動できます。**[PR]** タブでは、`c` で新しい一般コメント用のコンポーザーを開き、自分のコメント上での `e`/`d` はそれぞれ編集、(確認後に)削除を行い、説明文ブロック・issue コメント・レビューの上で `a` を押すとそれに対するリアクションピッカーが開きます。diff 上では、`c` は新しい行コメント用のコンポーザーを開きます(`V` による選択がアクティブな場合は範囲コメントになります――追加行と削除行が混在する選択はトーストで拒否されます)。既存のスレッド上では返信になります(`r` と同じ)。`C` はファイル全体へのコメント、`x` はスレッドの解決/未解決の切り替えです(スレッド以外の行ではトーストが表示されます)。スレッド上での `e`/`d` は、そこにある自分のコメントを編集または(確認後に)削除します――複数該当する場合は小さなメニューが表示されます。スレッド上で `a` を押すとそのコメントへのリアクションピッカーが開きます――自分のコメントに限らずすべてのコメントにリアクションでき、複数ある場合は同様に小さなメニューが表示されます。行/範囲/ファイルコメントや返信を送信すると、GitHub と同じ 2 択のボタン「Add single comment」または「Add to review」が表示されます。ただし、既にペンディング中のレビューが存在する場合は、メニューなしで常にそのレビューに追加されます。`p` は現在のプルリクエストのペンディング中のレビューコメントとローカルの下書きの一覧を開きます(`j`/`k` で移動、`Enter` で編集用に開く、`d` で削除、`D` でペンディング中のレビュー全体を破棄、`q`/`Esc` で閉じる)――この間、コンポーザーは開いたままになります(`Ctrl-w j`/`Ctrl-w k` でコンポーザーと開かれた元のペインの間のフォーカスを切り替え)。`S` はレビュー送信ダイアログを開きます。まず選択メニュー(Approve / Request changes / Comment)、次にレビュー本文用のコンポーザーが表示されます。送信すると `Store.SubmitReview` が呼び出され、成功すると PR 一覧が更新されます――本文が空でペンディング中のコメントもない Comment/Request changes レビューは拒否されます(Approve は本文を必要としません)。リアクションピッカー(`a`)には GitHub の 8 種類のリアクションが現在のカウントとともに表示され、自分が追加したものには `YOU` マーカーが付きます。`j`/`k` で移動、`Enter`/`Space` でカーソル位置のリアクションを切り替え、ピッカーは続けて操作できるよう開いたままになります。`q`/`Esc` で閉じます。プルリクエストがリアクションを許可していない場合、ピッカーを開こうとするとトーストで拒否されます。コンポーザー内では、`i a I A o O` でインサートモードに入り、`h j k l w b e 0 ^ $ gg G` で(カウント指定を伴って)移動し、`x X D C s S dd dw de d$ cc cw c$ yy yw p P` で操作し、`J` で行を結合し、`u`/`Ctrl-r` で undo/redo し、`v`/`V` で(行)ビジュアル選択を開始します。`@` はメンションポップアップを開きます(候補はまず PR 自体の参加者、続いてリポジトリの実際のメンション可能なユーザーで、あいまい検索でフィルタされます。`Ctrl-n`/`Ctrl-p`/矢印キーで移動、`Tab`/`Enter` で確定、`Esc` でポップアップのみを閉じます)。`Ctrl-s`/`:w` で送信、`:q`/`:q!` で下書きを保持/破棄してコンポーザーを閉じ、`:e` は `gprt` をサスペンドして設定済みの `editor`/`$EDITOR` でバッファを編集します。`?` はヘルプを表示し、`:` はコマンドライン(`:q`、`:help`、`:messages`、`:reload`)を開き、`q`/`Ctrl-c` で終了します(`Ctrl-c` は、コメントの送信・編集・削除の実行中には確認を求めます)。完全な一覧表、アクション ID、どのバインドが実装済みかについては [docs/KEYBINDINGS.md](docs/KEYBINDINGS.md) を参照してください。
